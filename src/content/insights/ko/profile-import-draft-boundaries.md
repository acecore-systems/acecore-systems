기존 프로필을 다른 편집기로 옮길 때는 먼저 현재 값과 가져오기 후보를 비교한 뒤 무엇을 바꿀지 결정해야 합니다. 이 일반화된 1단계 구현 사례에서 가져오기와 공개의 경계를 살펴봅니다.

## 먼저 지원하는 입력 형식을 정하기

이 단계에서는 텍스트, CSV, 정적 HTML을 지원합니다. 붙여넣은 내용이나 파일을 분석하는 것과 URL에 접속해 내용을 가져오는 것은 다릅니다. JSON, 이미지, 오디오, 동적 페이지, 외부 서비스 API는 완료된 구현 범위에 포함되지 않습니다.

HTML은 입력 데이터로만 취급합니다. script를 실행하거나 가져온 HTML 자체를 공개 페이지에 렌더링하지 않습니다. 텍스트 길이, 항목, 링크, 입력 형식에 제한을 두고 프로필에 필요한 텍스트 후보로 변환합니다.

## 후보 검토와 프로필 편집을 분리하기

분석 결과를 바로 공개하지 말고 현재 값과 후보를 먼저 비교합니다. 소유자가 항목별로 선택하고 후보 값을 편집한 뒤 편집기에 반영할 수 있습니다. 선택한 항목은 현재 값을 대체하므로 다시 가져올 때마다 차이를 확인해야 합니다. 저장 전에는 취소할 수 있지만, 자동으로 수동 편집을 보호하거나 충돌을 병합하는 기능이 완성되었다는 뜻은 아닙니다.

## 가져온 텍스트로 자격이나 권리를 추정하지 않기

자기소개나 외부 페이지의 표현만으로 자격, 소속, 분류, 라이선스가 자동으로 확인되지는 않습니다. 후보로 가져올 수 있는 설명과 본인 확인이나 신청이 필요한 정보를 구분합니다. 외부 정보가 바뀌어도 소유자가 확인한 프로필을 자동으로 갱신하거나 공개하지 않습니다.

## 저장과 공개를 별도의 결정으로 유지하기

가져온 후보 적용, 초안 저장, 공개 스냅샷 갱신은 각각 별도의 작업입니다. 저장 충돌은 수락 테스트에서 별도로 확인해야 하며, 저장 성공이 프로필 공개를 뜻하지는 않습니다. 공개 캘린더 URL을 포함한 링크는 공개 전에 값을 확인하고 개인 메모가 공개 데이터에 섞이지 않게 합니다.

## 관련 업데이트: 공개 일정에서 HTTPS 링크 열기

가져오기와 별개인 편집 개선으로 공개 캘린더 일정에 HTTPS 링크를 설정할 수 있게 했습니다. 공개 화면에서는 일정에서 목적지를 새 탭으로 직접 열고, 링크 없는 일정은 조작 가능한 링크 없이 표시합니다. URL 형식·내장 인증 정보 없음·입력 길이를 검증하고 `noopener noreferrer`를 붙이며 접근 가능한 이름에도 새 탭 동작을 설명합니다.

관련 입력 화면에서 협업 가능 시간대의 불필요한 제목 칸과 개인 메모 칸도 정리했습니다. DB 변경·CI·운영 배포·검증용 데이터의 화면은 확인했지만 실제 소유자가 로그인해 실제 일정을 저장·공개하는 수용 검사는 미확인입니다.

## 확인된 범위와 다음 수락 단계

1단계 가져오기 흐름의 구현, 통합, 프로덕션 배포를 확인했습니다. 하지만 실제 사용자가 가져오고 편집한 뒤 저장하고 공개된 화면까지 확인하는 전체 테스트는 완료되지 않았습니다. 활동 플랫폼 URL만으로 프로필 전체를 자동 작성하는 더 큰 구상도 완료되지 않았습니다.
