GUI로 프로필의 색상과 간격을 조정하고 제한된 CSS 문법을 직접 작성할 수도 있는 편집기는 사용성과 공개 페이지에 표시되는 코드의 안전성을 모두 고려해야 합니다. 익명화한 구현 사례를 바탕으로 편집과 배포의 경계를 살펴봅니다.

## 작은 문법으로 CSS 범위를 제한하기

임의의 CSS를 공개 페이지에 그대로 삽입하지 말고, 구문을 분석해 지원하는 구성요소, 속성, 값만 허용합니다. 현재 구현은 의도적으로 작은 문법만 허용하며, 더 자유로운 CSS 편집은 아직 완료되지 않은 추가 요청입니다. 이 사례에서는 선택된 클래스와 제한된 의사 클래스만 허용하고 외부 URL, at-rule, 제한 없는 속성 선택자, HTML 구분자, 과도한 규칙 수를 거부합니다.

허용된 CSS의 범위를 정해진 프로필 영역으로 제한하고 다시 생성한 뒤, 공개하기 전에도 재검증합니다. GUI 설정과 직접 작성한 원문은 편집용으로 보존하되, 공개 snapshot에는 검증된 CSS만 고정합니다. 범위만 제한한다고 임의의 CSS가 안전해지는 것은 아닙니다. 선택자 개념은 [W3C Selectors 명세](https://www.w3.org/TR/selectors-4/)를 참고하세요.

## 미리보기, 임시 저장, 공개를 분리하기

테마를 시험하거나 적용하면 임시 저장 내용이 바뀝니다. 소유자가 직접 공개하기 전에는 공개 페이지가 바뀌지 않습니다. 직접 작성한 CSS를 다시 편집할 수 있다는 점도 그 원문을 방문자에게 보내는 것과는 다릅니다. 저장 충돌을 감지하고 재시도는 멱등하게 처리해, 같은 작업을 다시 보내도 버전이나 임시 저장 내용이 중복 갱신되지 않게 합니다.

## 다른 작성자의 업데이트가 사용 중인 디자인을 바꾸지 않게 하기

바뀔 수 있는 테마 목록 정보와 불변 릴리스를 분리합니다. 사용자는 특정 버전 ID를 지정해 가져오므로 작성자가 새 버전을 공개해도 기존 임시 저장이나 공개 디자인은 조용히 바뀌지 않습니다. 편집 후에도 출처, 버전, 라이선스 표시를 보존합니다. 공개 프로필이 비공개로 바뀌어도 작성자의 임시 저장에 있는 이름이나 이미지가 배포 테마에 노출되지 않게 합니다.

## 목록에서 내리기와 운영자 중지를 구분하기

작성자가 테마를 목록에서 내리면 새로 찾거나 적용하지 못하게 할 수 있지만 이미 고정된 버전을 바로 철회하는 것은 아닐 수 있습니다. 위험한 테마를 운영자가 중지할 때는 기존 snapshot 안의 CSS까지 제공을 중단하고 기본 모양으로 되돌리는 별도의 경계가 필요합니다. 이전 snapshot으로 롤백한 뒤에도 현재 중지 상태를 확인해 중지 전 CSS가 되살아나지 않게 합니다.

## 공개 전에 확인할 항목

범위를 벗어난 선택자, 외부 요청, 입력 크기, 저장 충돌, 재시도, 작성자의 비공개 전환, 목록 제외, 운영자 중지, 롤백을 시험합니다. 코드, 배포, 테스트 데이터 표시를 확인했지만 실제 사용자가 테마를 제출하고 다른 사용자가 적용하는 전체 흐름을 시험했다는 뜻은 아닙니다. 라이선스 조건도 브라우저에 전달된 CSS가 절대 복사되지 않는다고 보장하지 않습니다.
