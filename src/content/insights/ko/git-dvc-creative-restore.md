## Git과 DVC에서 무엇을 일치시킬까

Git에는 편집 프로젝트, 소재 대장, DVC 참조 정보를 저장하고, 대용량 영상·음성 소재는 DVC로 관리합니다. 소재의 출처와 이용 조건도 대장에 기록합니다. Git에 참조가 있다는 것만으로는 소재 원본이 저장되었다는 증거가 되지 않으므로, 저장소에 업로드되었는지와 독립적으로 가져올 수 있는지를 별도로 확인합니다. [DVC의 pull 설명](https://doc.dvc.org/command-reference/pull)에서 참조에 대응하는 데이터를 가져오는 방법을 확인할 수 있습니다.

## 빈 캐시에서 복원해 대조하기

사내 동영상 제작 기반에서는 독립적인 빈 캐시를 사용해 2개 버전을 전환하고, 원래 버전으로 되돌린 소재의 SHA-256을 대조했습니다. 편집 정의의 상대 참조도 확인했으며, 원본과 복원본에서 생성한 8초 동영상은 바이트 단위로 일치했습니다. 이는 제한적인 로컬 복원과 내보내기의 결과로, 외부 저장소나 다른 PC에서의 복원 또는 편집 화면에서의 재저장을 증명하지는 않습니다.

다른 동영상 버전에서는 60개 소재를 로컬 저장소에서 빈 캐시로 복원하고, 해시와 편집 정의의 참조를 대조했습니다. 이 시험에서는 클라우드 동기화나 편집 화면에서의 다시 불러오기는 수행하지 않았습니다. 저장소가 바뀐다면 새로운 저장소를 대상으로 같은 절차를 다시 수행합니다.

음악 제작의 다른 시험에서는 독립적인 로컬 캐시에서 7개 미디어를 복원하고, 해시와 크기, 3개 스템과 영상 편집 정의의 상대 참조를 대조했습니다. Ardour의 native 처리로 저장·다시 불러오기·전체 길이 출력을 수행했으며, 고정된 WAV와의 PCM 차이는 0이었습니다. 이는 native 처리에 의한 확인입니다. 화면을 조작해 편집·다른 이름으로 저장·다시 열기를 수행하는 일련의 GUI 확인, 외부 저장소에서의 신규 복원, 다른 PC에서의 확인은 이 시험에서 수행하지 않았습니다.

## 재생할 수 있는지와 편집할 수 있는지 확인하기

1. 원본을 덮어쓰지 않는 위치에 대상 Git 버전과 소재를 복원합니다.
2. 대장의 해시, 참조 경로, 소재 누락 여부를 확인합니다.
3. 내보낸 영상이나 음성을 재생해 길이와 누락 여부를 확인합니다.
4. 편집 앱에서 열어 다른 이름으로 다시 저장한 뒤, 다시 열어 편집 상태를 확인합니다.

앱 버전, 글꼴, 플러그인, 음원과 권리도 복원에 영향을 줍니다. 자동 비교 결과가 일치하더라도 소리와 화면의 품질이 의도에 맞는지는 사람이 확인해야 합니다. 먼저 가상의 소재로 만든 짧은 프로젝트에서 일련의 절차를 시험하고, 확인 날짜와 확인하지 않은 저장소를 기록하세요. 확인 날짜: 2026년 11월 17일.
