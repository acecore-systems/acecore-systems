## 같은 데스크톱을 공유 자원으로 취급하기

자동화마다 별도의 잠금을 가지고 있더라도 실제로 같은 화면에 입력한다면 충돌을 막을 수 없습니다. 같은 데스크톱을 사용하는 처리가 공통의 상호 배제에 참여하고, 잠금을 획득하지 못한 처리는 클릭이나 입력 전에 중단합니다. 공유 자원에 대한 동시 접근을 제어하는 메커니즘의 예로 [Windows의 뮤텍스 설명](https://learn.microsoft.com/en-us/windows/win32/sync/using-mutex-objects)도 참고할 수 있습니다.

입력과 화면 전환 중에는 상호 배제를 유지하고, 전송 전에 현재 화면과 접속 대상을 다시 확인합니다. 대기 시간이 긴 외부 처리까지 화면을 계속 점유해야 하는지는 실제로 화면을 사용하는 범위를 확인해 판단합니다. 예외 발생 시 해제, 처리 중단 후의 화면 상태, 결과를 알 수 없는 전송을 어떻게 다룰지도 설계에 포함합니다.

## 합성 화면에서 확인한 내용

사내에 등록된 인증 경로에서는 화면 전환과 전송 전 재확인 및 조작을 공유 상호 배제의 범위에 포함했습니다. 고정된 합성 화면에서 전송 성공, 충돌로 인한 중단, 다중 요소 인증으로의 전환, 클릭 시 예외를 검증했습니다. 실제 인증 정보를 사용한 시험이나 모든 사이트에서의 동작을 보여 주는 것은 아닙니다.

전송이 한 번 이루어졌는지 불명확할 때는 재전송을 반복하지 말고 대상 측의 상태를 확인합니다. 잠금은 잘못된 입력의 위험을 줄이는 장치이며, 본인 확인, 인가, 입력 내용이나 전송 결과의 확인을 대신하지 않습니다.

## 먼저 시도할 것

가상의 양식을 준비하고 두 처리를 동시에 시작합니다. 한쪽만 조작하고 다른 쪽은 입력 전에 중단하는지, 처리 도중 예외가 발생해도 다음 처리가 재개될 수 있는지 확인합니다. 도중에 화면이 바뀌는 경우도 추가하고, 재확인에 실패하면 전송하지 않도록 합니다. 확인일: 2026년 11월 17일.
