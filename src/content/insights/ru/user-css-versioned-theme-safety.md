Редактор профиля, в котором можно менять цвета и отступы через GUI, а при необходимости писать CSS ограниченного формата, должен учитывать и удобство интерфейса, и безопасность кода, отображаемого на публичных страницах. Этот обезличенный пример помогает разделить редактирование и распространение.

## Ограничивайте CSS небольшой грамматикой

Не вставляйте произвольный CSS напрямую в публичную страницу. Разберите синтаксис и разрешайте только поддерживаемые компоненты, свойства и значения. Текущая реализация намеренно принимает небольшую грамматику; более свободное редактирование CSS остается незавершенным дополнительным запросом. В этом варианте разрешены выбранные классы и ограниченный набор псевдоклассов; внешние URL, at-rule, произвольные селекторы атрибутов, HTML-разделители и чрезмерное число правил отклоняются.

Ограничивайте принятый CSS заданной областью профиля, повторно генерируйте его и еще раз проверяйте перед публикацией. Сохраняйте настройки GUI и исходный текст CSS для редактирования, но фиксируйте в публичном snapshot только проверенный CSS. Одна лишь область действия не делает произвольный CSS безопасным. О принципах селекторов см. [спецификацию W3C Selectors](https://www.w3.org/TR/selectors-4/).

## Разделяйте предпросмотр, черновик и публикацию

Примерка или применение темы меняет черновик. Публичная страница меняется только после публикации ее владельцем. Возможность повторно редактировать написанный вручную CSS также не означает, что его исходный текст отправляется посетителям. Обнаруживайте конфликты сохранения и делайте повторы идемпотентными, чтобы повторная отправка той же операции не обновляла версию или черновик дважды.

## Не позволяйте обновлению другого автора менять активный дизайн

Разделяйте изменяемые сведения в каталоге тем и неизменяемые версии. Пользователь импортирует конкретный ID версии, поэтому новая версия автора не должна незаметно менять существующий черновик или опубликованный дизайн. Сохраняйте источник, версию и атрибуцию лицензии после редактирования. Если публичный профиль становится приватным, имя или изображение из черновика автора не должны попасть в распространяемую тему.

## Различайте снятие с публикации и административную блокировку

Автор может снять тему с публикации, запретив ее дальнейшее обнаружение и применение, но это не обязательно сразу отзывает уже закрепленную версию. Для административной блокировки опасной темы нужна отдельная граница: прекратить отдавать ее CSS, в том числе из существующих snapshots, и вернуться к стандартному оформлению. После отката на старый snapshot проверьте текущий статус блокировки, чтобы CSS до блокировки не восстановился.

## Что проверить перед публикацией

Проверьте неподдерживаемые селекторы, внешние запросы, размер входных данных, конфликты сохранения, повторы, перевод профиля автора в приватный режим, снятие с публикации, административную блокировку и откат. Код, публикация и отображение тестовых данных были проверены, но это не сквозной тест, в котором реальный пользователь отправляет тему, а другой применяет ее. Условия лицензии также не гарантируют, что CSS, доставленный в браузер, никогда не скопируют.
