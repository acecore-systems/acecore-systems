Это описание реализации для тех, кто хочет сделать японский блог на Astro многоязычным и при этом надёжно управлять URL переводов, переключением языков, sitemap и hreflang. Сначала согласуйте основной текст, метаданные и переключение языков на примере одной статьи и убедитесь, что пользователи не попадают на непереведённые страницы. Используйте [Astro: Internationalization Routing](https://docs.astro.build/en/guides/internationalization/) как основу для проектирования URL и постепенно расширяйте переводы интерфейса и статей отдельно друг от друга. Приведённые ниже количества и прежняя конфигурация CMS относятся к моменту внедрения.

> **Дополнение от 2026 года, 9 месяца, 26 числа:** Astro 7.1.3, количество статей и перевод с помощью Copilot в тексте относятся к 2026 году, 7 месяцу. В [текущем объявлении зависимостей](https://github.com/acecore-systems/acecore-net/blob/main/package.json) указаны Astro ^7.3.3 и Tailwind CSS 4.3.3; текущий процесс перевода описан в [статье об переходе на OpenAI Batch](/insights/copilot-translation-pipeline/). Прежде чем использовать приведённые примеры реализации и числовые показатели как текущую конфигурацию, проверьте актуальный исходный код и опубликованные страницы.

## Реализация по состоянию на 2026 год, 7 месяц

Мы расширили официальный сайт Acecore с японского до поддержки 9 языков. При первоначальном внедрении было переведено 21 статей × 8 языков = 168 переводов. На 2026 год, 7 месяц, 29 число было 29 статей на японском и 208 переводов, всего 237 статей; сборка создавала 652 страниц. Для локалей без перевода URL статьи не создаётся: публикуются только существующие языковые версии.

## Подход к многоязычности и проектирование URL

Мы поэтапно внедрили многоязычность в следующих 3 областях.

1. **Создание инфраструктуры i18n**: настройка встроенной i18n-маршрутизации Astro, утилиты перевода и JSON-файлы переводов для 9 языков
2. **Перевод текстов интерфейса**: тексты компонентов шапки, подвала, боковой панели и всех страниц
3. **Перевод статей блога**: при первоначальном внедрении 21 статья переведена на 8 языков (создано 168 файлов)

### Проектирование URL

Мы используем `prefixDefaultLocale: false` в Astro: японская версия доступна непосредственно в корне (`/blog/...`), а остальные языки — с префиксами (`/en/blog/...`, `/zh-cn/blog/...` и т. д.).

```
# 日本語（デフォルト）
/blog/astro-performance-tuning/

# 英語
/en/blog/astro-performance-tuning/

# 簡体字中国語
/zh-cn/blog/astro-performance-tuning/
```

Поскольку во всех языках используется один и тот же slug, сопоставлять URL при переключении языка просто.

Автоматизация с помощью Copilot для постоянной работы с переводами описана в статье [Как управлять многоязычным блогом с помощью Sveltia CMS](/insights/copilot-translation-pipeline/).

## Настройка инфраструктуры i18n в Astro

### Настройка i18n в Astro

Настроим i18n-маршрутизацию в `astro.config.mjs`.

```javascript
// astro.config.mjs
export default defineConfig({
  i18n: {
    defaultLocale: "ja",
    locales: ["ja", "en", "zh-cn", "es", "pt", "fr", "ko", "de", "ru"],
    routing: {
      prefixDefaultLocale: false,
    },
  },
});
```

### Утилиты перевода

Мы собрали файлы конфигурации, служебные функции и JSON-файлы переводов в `src/i18n/`.

```typescript
// src/i18n/utils.ts
export function t(locale: Locale, key: string): string {
  return translations[locale]?.[key] ?? translations[defaultLocale][key] ?? key;
}
```

Файлы переводов для каждого языка размещены в формате JSON в `src/i18n/locales/`. Они содержат около 100 ключей для навигации, подвала, интерфейса блога, метаданных и других элементов.

### Паттерн компонентов View

Для реализации страниц мы используем **паттерн компонентов View**. Макет и логика сосредоточены в `src/views/`, а файлы маршрутов (`src/pages/`) служат тонкими обёртками, которые лишь передают локаль.

```astro
---
// src/pages/[locale]/about.astro（ルートファイル）
import AboutPage from "../../views/AboutPage.astro";
const { locale } = Astro.params;
---

<AboutPage locale={locale} />
```

Благодаря такой архитектуре дублирование логики между японским маршрутом (`/about`) и многоязычным маршрутом (`/en/about`) исключено.

## Перевод статей блога в отдельных каталогах языков

### Структура каталогов

Переведённые статьи размещаются в подкаталогах с кодами языков. Загрузчик glob в Astro автоматически обнаруживает их рекурсивно по шаблону `**/*.md`. В [Content Loader API](https://docs.astro.build/en/reference/content-loader-reference/) Astro указано, что для `pattern` загрузчика `glob()` можно задать globstar, например `**/*.md`, и загружать файлы Markdown и другие файлы из каталогов.

```
src/content/blog/
  astro-performance-tuning.md          # 日本語（ベース）
  website-renewal.md
  en/
    astro-performance-tuning.md        # 英語版
    website-renewal.md
  zh-cn/
    astro-performance-tuning.md        # 簡体字中国語版
    website-renewal.md
  es/
    ...
```

### Утилиты разрешения контента

Мы реализовали 3 функции в `src/utils/blog-i18n.ts`.

```typescript
// ベース記事かどうかを判定（IDにスラッシュが無い = ベース）
export function isBasePost(post: CollectionEntry<"blog">): boolean {
  return !post.id.includes("/");
}

// IDからロケールプレフィックスを除去してベーススラッグを取得
export function getBaseSlug(postId: string): string {
  const idx = postId.indexOf("/");
  return idx !== -1 ? postId.slice(idx + 1) : postId;
}

// ベース記事のローカライズ版を取得（無ければ原文にフォールバック）
export function localizePost(
  post: CollectionEntry<"blog">,
  allPosts: CollectionEntry<"blog">[],
  locale: Locale,
): CollectionEntry<"blog"> {
  if (locale === defaultLocale) return post;
  return allPosts.find((p) => p.id === `${locale}/${post.id}`) ?? post;
}
```

Сама `localizePost()` в качестве защитного механизма возвращает оригинал, но публичные маршруты и списки с помощью `isPostAvailableInLocale()` и фильтров включают только существующие переводы. Поэтому URL статьи для непереведённой локали не создаётся.

Главное здесь — **не изменять существующую схему коллекции контента**. Загрузчик glob в Astro автоматически распознаёт файлы в подкаталогах с идентификаторами вида `en/astro-performance-tuning`, поэтому менять конфигурацию не потребовалось.

### Правила для файлов перевода

Файлы переводов создавались по следующим правилам:

- **Ключи frontmatter** остаются на английском (`title`, `description`, `date` и т. д.)
- **Значения тегов** сохраняются на японском (`['技術', 'Astro']` и т. д.)
- **URL, пути к изображениям, блоки кода и HTML** не изменяются
- **Даты и авторы** не изменяются
- **Основной текст и текстовые значения frontmatter** (title, description, callout, FAQ и т. д.) переводятся

### Рабочий процесс перевода

Процесс перевода выглядит следующим образом:

1. **Создание английской версии как промежуточной**: перевод японского оригинала на английский
2. **Перевод с английского на остальные языки**: перевод на 7 языков с английской версии
3. **Пакетная обработка**: обработка с помощью GitHub Copilot партиями по 5–6 статей

Перевод в 2 этапа — с японского на английский, а затем на остальные языки — снижает разброс качества. Использование английского как промежуточного языка дало более стабильное качество, чем прямой перевод с японского на каждый язык.

## Многоязычная поддержка компонентов View

### Реализация BlogPostPage

На странице статьи блога контент для локали извлекается с помощью `localizePost()` и присваивается переменным шаблона.

```astro
---
// src/views/BlogPostPage.astro
const localizedPost = localizePost(basePost, allPosts, locale);
const post = localizedPost; // テンプレートの既存参照がそのまま動く
---
```

Этот подход позволил добавить многоязычность, не меняя ссылки на `post.data.title` и `post.body` внутри шаблона.

### Страницы списков

На страницах списка блога, тегов, авторов и архива с помощью `isBasePost()` отбираются только базовые статьи, а при отображении они заменяются переводами с помощью `localizePost()`.

```astro
---
const allPosts = await getCollection("blog");
const basePosts = allPosts.filter(isBasePost);
const displayPosts = basePosts.map((p) => localizePost(p, allPosts, locale));
---
```

## Проблемы с YAML и OG-изображениями при сборке

### Экранирование frontmatter в YAML

Во французских переводах возникла проблема: апострофы (`l'atelier`, `qu'on` и т. д.) конфликтовали с одинарными кавычками YAML.

```yaml
# NG：YAML パースエラー
title: 'Le métavers est plus proche qu'on ne le pense'

# OK：ダブルクォートに変更
title: "Le métavers est plus proche qu'on ne le pense"
```

Мы исправили все файлы скриптом Node.js. Аналогичная проблема встречается и в английском, например в `Acecore's`, поэтому при создании файлов перевода нужно следить за типом кавычек.

### Фильтрация маршрутов OG-изображений

`/blog/og/[slug].png.ts` также захватывал slug переведённых статей (например, `en/aceserver-hijacked`), что приводило к ошибке параметров. Мы решили проблему фильтрацией через `isBasePost()`.

```typescript
export const getStaticPaths: GetStaticPaths = async () => {
  const allPosts = await getCollection("blog");
  const posts = allPosts.filter(isBasePost);
  return posts.map((post) => ({
    params: { slug: post.id },
    props: { title: post.data.title },
  }));
};
```

## Многоязычная поддержка Pages CMS

Pages CMS (`.pages.yml`) обрабатывает только файлы непосредственно в каталоге, указанном в `path`, поэтому подкаталоги переводов были зарегистрированы как отдельные коллекции.

```yaml
content:
  - name: blog
    label: ブログ（日本語）
    path: src/content/blog
  - name: blog-en
    label: Blog（English）
    path: src/content/blog/en
  - name: blog-zh-cn
    label: 博客（简体中文）
    path: src/content/blog/zh-cn
  # ... 各言語ごとに設定
```

Названия коллекций указаны на соответствующих языках, поэтому в CMS сразу видно, к какому языку относится каждая коллекция.

## Интерфейс переключения языков

Мы добавили компонент `LanguageSwitcher` в шапку и реализовали переключение языков как для компьютеров, так и для мобильных устройств. При переключении пользователь переходит на соответствующую локаль той же страницы, а при первом посещении определяется `navigator.language` браузера и выполняется автоматическое перенаправление.

## Многоязычное отображение тегов

Для тегов статей мы сохранили японские slug в URL, а **переводим только отображаемые названия**. Это позволяет избежать усложнения маршрутизации и показывать пользователям теги на их языке.

Определения тегов собраны в `src/content/tags/{tagId}.json`, и каждый тег содержит `i18n.name`. Таким образом, источником истины для переводов тегов становится коллекция тегов, а не JSON-файлы переводов.

```json
{
  "id": "technology",
  "name": "技術",
  "i18n": {
    "en": { "name": "Technology" },
    "fr": { "name": "Technologie" }
  }
}
```

Карточки статей, боковая панель, список тегов и страницы статей обращаются к коллекции tags для переключения названий, поэтому все теги отображаются на языке выбранной локали.

## Многоязычная поддержка данных авторов

Мы также добавили переключение имени автора, биографии (bio) и списка навыков в зависимости от языка. Поле `i18n` добавлено в `src/content/authors/{authorId}.json` для хранения переводов на каждый язык.

```json
{
  "id": "hatt",
  "name": "ハット",
  "bio": "代表取締役。Web制作・サーバー運用…",
  "skills": ["TypeScript", "Astro", "..."],
  "i18n": {
    "en": {
      "name": "Hatt",
      "bio": "CEO and representative director. Web development...",
      "skills": ["TypeScript", "Astro", "..."]
    }
  }
}
```

Утилита `getLocalizedAuthor()` извлекает данные автора для выбранной локали.

```typescript
// src/utils/blog-i18n.ts
export function getLocalizedAuthor(author: Author, locale: Locale) {
  const localized = author.i18n?.[locale];
  return localized ? { ...author, ...localized } : author;
}
```

## Реализация многоязычного SEO

Чтобы максимально использовать преимущества многоязычности для SEO, мы настроили механизмы, позволяющие поисковым системам корректно распознавать и индексировать каждую языковую версию.

### Поддержка hreflang в карте сайта

Мы настроили опцию `i18n` в `@astrojs/sitemap` и фильтр, проверяющий наличие файлов перевода. В карту сайта включаются только существующие языковые версии, а соответствующие теги `xhtml:link rel="alternate"` выводятся автоматически.

```javascript
// astro.config.mjs
sitemap({
  filter(page) {
    return !isMissingLocalizedBlogPost(page);
  },
  i18n: {
    defaultLocale: "ja",
    locales: {
      ja: "ja",
      en: "en",
      "zh-cn": "zh-CN",
      es: "es",
      pt: "pt",
      fr: "fr",
      ko: "ko",
      de: "de",
      ru: "ru",
    },
  },
});
```

Для статьи, существующей на всех 9 языках, выводится hreflang для 9 языков. Для статьи без переводов указывается только японский URL; несуществующие языковые версии не включаются в sitemap и hreflang.

### Язык в структурированных данных JSON-LD

Мы добавили поле `inLanguage` в структурированные данные `BlogPosting` статей блога, чтобы сообщать поисковым системам язык каждой статьи.

```javascript
// BlogPostPage.astro（JSON-LD 抜粋）
{
  "@type": "BlogPosting",
  "inLanguage": htmlLangMap[locale],  // "ja", "en", "zh-CN" など
  "headline": post.data.title,
  // ...
}
```

### Многоязычные RSS-ленты

Помимо японской `/rss.xml`, мы создаём RSS-ленты для каждой языковой версии (`/en/rss.xml`, `/zh-cn/rss.xml` и т. д.). Названия и описания лент также переводятся на соответствующие языки, а тег `<language>` содержит код языка в соответствии с BCP47.

```typescript
// src/pages/[locale]/rss.xml.ts
export const getStaticPaths = () =>
  locales
    .filter((l) => l !== defaultLocale)
    .map((l) => ({ params: { locale: l } }));
```

В `<link rel="alternate" type="application/rss+xml">` компонента `BaseLayout.astro` также автоматически устанавливается URL RSS для соответствующей локали.

## Итоги

В реализации на 2026 год, 7 месяц встроенные функции i18n в Astro 7.1.3 позволяют поддерживать несколько языков даже на статическом сайте.

- **Инфраструктура i18n**: с `prefixDefaultLocale: false` в Astro японский язык не имеет префикса
- **Перевод интерфейса**: паттерн компонентов View исключает дублирование логики
- **Перевод контента**: использование подкаталогов не требует изменения существующей схемы
- **Перевод тегов**: японские slug остаются в URL, переводятся только отображаемые названия
- **Перевод данных авторов**: bio и skills переключаются в зависимости от языка
- **SEO**: hreflang в карте сайта, `inLanguage` в JSON-LD и многоязычные RSS-ленты
- **Непереведённые локали**: URL статьи не создаётся, а японская версия остаётся доступной по исходному URL
- **Поддержка CMS**: статьи на каждом языке можно редактировать отдельно в Pages CMS

В дальнейшем файлы переводов будут добавляться постепенно по мере появления новых статей. Пока перевод не готов, публикуется только японская версия; URL статьи, sitemap и hreflang включаются для локалей, в которых добавлен файл перевода.

## Дополнение от 2026 года, 10 месяца, 6 числа: язык экранов аутентификации и ошибки

Помимо перевода опубликованных статей, последовательный выбор языка необходим и на экранах аутентификации. В анонимизированной доработке язык выбирался по порядку из поддерживаемых `ui_locales`, `Accept-Language` и языка по умолчанию; для неподдерживаемых значений предусмотрен безопасный резервный вариант. Известные ошибки OIDC преобразуются в общие сообщения для отображения, а для неизвестных ошибок внутренние сообщения не показываются пользователю в исходном виде.

Метки страниц, ошибки через API и сообщения после завершения регистрации проверяются совместно. Поддержка 9 языков в блоге сама по себе не означает, что приёмка всех экранов аутентификации и реальных сценариев регистрации завершена.

Язык также сохраняется при входе, управлении учётной записью, предоставлении согласия и использовании одноразового кода; locale и state OIDC сохраняются при переходах. Проверка URL, Content-Language и отображения на узких экранах рассматривается отдельно от пользовательской приёмки на всех языках.
