将已有个人资料迁移到另一个编辑器时，应先比较当前值与导入候选，再决定是否替换。本文以匿名化的第一阶段实现为例，说明导入与发布之间的边界。

## 先明确支持的输入格式

此阶段支持文本、CSV 和静态 HTML。解析粘贴的内容或文件，与访问 URL 获取其内容是两件不同的事。JSON、图片、音频、动态页面和外部服务 API 均不属于已完成的实现。

将 HTML 仅作为输入数据处理，不要在公开页面执行其中的脚本或直接渲染导入的 HTML。对文本长度、字段、链接和输入格式设定限制，再将来源内容转换为个人资料需要的文本候选。

## 将候选审阅与编辑资料分开

不要立即发布解析结果；先比较当前值与候选内容。资料所有者逐项选择字段，也可以先编辑候选值，再将其应用到编辑器。选中的字段会替换当前值，因此每次重新导入都需要查看差异。保存前可以撤销，但这并不表示自动保护手动编辑或冲突合并功能已经完成。

## 不从输入内容推断资质或权利

简介或外部页面中的措辞不能自动证明资质、所属关系、类别或许可证。将可作为候选导入的说明文字，与需要身份核验或申请的信息分开。外部信息发生变化时，也不会自动更新或发布所有者确认过的个人资料。

## 将保存与发布保留为不同的决定

应用导入候选、保存草稿和更新公开快照是不同操作。验收测试仍需覆盖保存冲突；保存成功不代表资料已经发布。发布关联链接（包括公开日历 URL）之前应由本人检查其公开值，并避免把私人备注混入公开数据。

## 相关更新：从公开日程打开HTTPS链接

另一项与导入独立的编辑更新，为公开日历的日程增加HTTPS链接。公开页面可从日程直接在新标签页打开目标；没有链接的日程只显示，不创建可操作的链接。验证URL格式、不含嵌入凭据及输入长度，添加 `noopener noreferrer`，并在可访问名称中说明会打开新标签页。

相关表单还整理了协作可用时段的不必要标题字段和私人备注字段。数据库修改、CI、生产部署及验证数据的显示已确认；本人登录后保存真实日程并公开的受验仍未确认。

## 已确认的内容与下一步验收

已确认第一阶段导入流程的实现、集成和生产部署。不过，真实用户从导入、编辑、保存到检查发布结果的端到端测试尚未完成。根据活动平台 URL 自动生成完整个人资料的更大构想也尚未完成。
