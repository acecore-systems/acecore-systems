即使通过 Search Console 的展示次数和点击次数找到待改进的文章，仅凭数据也无法判断读者是否得到了所需的答案。本文介绍如何调查页面和搜索意图，对照公开信息与正文审阅修订方案，并在发布后比较条件相同的时间段。

## 1. 根据数据和正文选择待改进内容

在搜索效果报告中固定页面、搜索类型和时间段，查看展示次数、点击次数、CTR 和平均排名。必要时也要查看搜索词、国家和设备。有展示次数但正文中难以找到答案的页面可作为调查候选，但仅凭较低的 CTR 无法判断是否需要修改标题。

打开页面，列出搜索者想了解什么，以及当前正文缺少哪些说明。同样重要的是，不要将未显示的搜索词或未获取的数据行视为没有搜索的证据。Google 的[搜索流量下降调查指南](https://developers.google.com/search/docs/monitor-debug/debugging-search-traffic-drops)可作为按时间段、页面和搜索词调查变化的参考。

## 2. 核对依据，形成对读者有用的修改

查阅官方资料和实际公开页面，补充具体示例、步骤、适用条件和参考链接。区分实测数据、用于说明的虚构示例和未经确认的事项，不要把未取得的效果写成成果。标题和 description 也要与正文实际回答的内容保持一致。[Google 的实用内容自我评估指南](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)也可作为审校参考。

将修订方案整理到 Draft PR 中，确认修改位置和出处、发布日期及 URL 是否保持不变，以及是否有待翻译内容。审查、合并、部署和被搜索引擎收录是不同的状态。仅完成正文审校，并不意味着内容已可在生产环境中阅读。

## 3. 固定发布日期和比较条件

例如，可以比较不含发布日期的前28天和后28天。两个时间段的目标 URL、语言、搜索类型、国家、设备、日期边界和数据确定状态应保持一致。如果发布日期当天的部署时间不统一，排除当天可以使比较条件更明确。28天是实务中的观察窗口，并不保证它是所有文章的最佳周期。

| 记录项目                          | 确认原因                     |
| --------------------------------- | ---------------------------- |
| 发布日期和时间、目标 URL          | 固定比较时间段和对象         |
| 点击次数、展示次数、CTR、平均排名 | 在相同条件下观察变化         |
| 语言、搜索类型、国家、设备        | 避免因统计口径不同而产生混淆 |
| 其他修订、需求、数据不足          | 记录解读变化所需的限制条件   |

## 实例：仅凭前后比较无法确定修订效果

在 Aceserver Portal 的[WIKI 与阿尔法君介绍文章](https://asv.acecore.net/zh-cn/stories/wiki-alpha-guide/)中，我们增加了提问示例和查阅原文的指引，并于2026年10月10日发布了修订版。评估窗口按 Search Console 的日期边界排除发布日期，分别为9月12日至10月9日，以及10月11日至11月7日。

前一时间段还包含首次发布日期和紧接此次修订之前的另一次修订。由于同时进行了多项修改，且搜索需求和较少的数据量也会造成波动，不能将前后差异解释为此次修订或参考链接单独产生的效果。截至调查时，流量改善尚未得到证实。记录观察值时，应区分已获取和未获取的数据范围。

不妨先针对一篇文章，记录读者的疑问、已发布的正文、核实过的出处和修订假设，形成可供审查的修改。将发布后的比较作为选择下一步调查的参考，并将数据变化与其原因分开处理。确认日期：2026年11月17日。
