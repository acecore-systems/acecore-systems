如果个人资料编辑器允许用户通过 GUI 调整颜色和间距，也允许手写有限的 CSS 语法，就必须同时考虑操作体验和公开页面中代码的安全性。下面将匿名化的实现经验整理为编辑与分发之间的边界。

## 用小型语法限制 CSS 范围

不要把任意 CSS 直接插入公开页面。应先解析语法，只允许受支持的组件、属性和值。当前实现有意限定为小型语法；更自由的 CSS 编辑仍是尚未完成的额外需求。该实现只接受选定的 class 和有限的伪类，并拒绝外部 URL、at-rule、任意属性选择器、HTML 分隔符和过多规则。

将通过验证的 CSS 限定到指定的个人资料区域，重新生成后，在发布时再次验证。保留 GUI 设置和手写原文供编辑，但只把已验证的 CSS 固定到公开快照中。仅添加作用域并不能让任意 CSS 变得安全。选择器概念可参阅 [W3C Selectors 规范](https://www.w3.org/TR/selectors-4/)。

## 分开预览、草稿和发布

试用或应用主题只会改变草稿。只有用户主动发布后，公开页面才会变化。可以再次编辑手写 CSS，也不代表要把原文发送给访客。应检测保存冲突，并让重试具备幂等性，避免重复提交同一操作时多次更新版本或草稿。

## 不让其他作者的更新改变正在使用的设计

将可变的主题列表信息与不可变的发布版本分开。用户按指定的版本 ID 导入主题，因此作者发布新版不会悄悄改变已有草稿或已发布设计。编辑后仍要保留来源、版本和许可出处。公开个人资料转为私密状态时，也不要让作者草稿中的名称或图片泄露到分发的主题中。

## 区分下架与运营停用

作者下架主题可以阻止新的发现和应用，但未必立即撤销已经固定版本的使用。运营者停用危险主题需要另一种边界：停止提供其 CSS，包括现有快照中的 CSS，并回退到标准外观。回退到旧快照后仍须检查当前停用状态，避免恢复停用前的 CSS。

## 发布前的检查项目

测试超出范围的选择器、外部请求、输入大小、保存冲突、重试、作者转为私密、下架、运营停用和回退。代码、发布和测试数据的显示均已检查，但这不代表真实用户提交主题、其他用户再应用主题的端到端测试。许可条款也无法保证发送到浏览器的 CSS 永远不会被复制。
